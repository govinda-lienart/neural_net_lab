📏 …and how the loss is calculated

Three steps: e^score to make everything positive, divide by the total to get percentages (that's softmax), then the loss is how little probability the true fish received. Together this is nn.CrossEntropyLoss.
Fire a crop to see the loss worked out. ☝️

📌 What loss should you expect?

With 5 fish, a model that knows nothing spreads its confidence evenly — 20% each. So −ln(0.20) = 1.61 is the clueless baseline, and every other number reads against it.

≈ 1.61knows nothing 🎲
≈ 0.70getting somewhere
≈ 0.10confident, usually right 😎
2.5 +worse than guessing 😬

A fresh random head should start near 1.61. If it's still there after several epochs, something is broken — frozen head, wrong learning rate, or bad labels. Cheapest sanity check you have on day one.

📈 Watch one wire learn

Keep alternating ← Backprop → 🎛️ Apply on the same crop. This tracks the first wire into the true fish, step by step. Notice the changes getting smaller as the loss falls — the weight is pacing itself.
Fire a crop to start tracking. ☝️

What you're seeing 👀

• Every one of the 6 inputs connects to every one of the 5 outputs → 6 × 5 = 30 wires = 30 weights (your real head: 384 × 5 ≈ 1,920).
• Forward: each output = sum of (input × wire weight). Highest wins = the guess.
• Backprop: if the guess is wrong, wires leading to the answer get "blamed" — they glow by how much they'd change. That glow is the gradient per weight.
• Apply the update: nudges all 30 wires by weight − 0.5 × gradient. Fire the same crop again and the loss will be lower — every time. That's the full loop.

The dimension ladder 🪜

0-D scalar — one number -1.33
1-D vector — a row [..]
2-D matrix — one grid 224×224
3-D tensor — your crop (3,224,224)
4-D tensor — a batch (32,3,224,224)
A tensor is just the umbrella word for a grid of numbers with any number of dimensions. Add a dimension → same thing, one level up.

…and this is the only part MLflow ever sees 📉

Below is the shared loss, logged once per step — mlflow.log_metric("train_loss", loss.item(), step=i). Six weights moved, six different gradients were computed, and none of that appears here. Just the one number.
The chart's horizontal axis is time (steps) — not a weight value. That's the difference between this chart and the six hills above: same vertical axis (loss), completely different horizontal one.
What one dot really is. This toy has no crops, so each dot is just the loss after one nudge. In real training, one step = one batch of crops (say 16) forward and back, and the dot is the average of those 16 losses. So a dot is a batch average, not a single crop — and not a summary of the gradients, which never appear on this chart at all.
